# AdminCabinet — agent guide

Phalcon MVC web GUI: controllers/forms/views here, JS in `sites/admin-cabinet/assets/js/src/`
(compiled to `js/pbx/`, see root AGENTS.md). Read the code for structure; this file is only
what the code does not tell you.

## Adding a section
- A controller alone loads no JS/CSS. `AssetProvider` calls `make<ControllerName>Assets($action)`
  by naming convention (`method_exists`); add that method or the page ships without scripts.
- Views are picked as `Views/<Controller>/<action>.volt`; external modules resolve to
  `Modules/<ModuleUniqueId>/<Controller>/<action>` (`BaseController::initialize()`).
- Menu entries live in `Library/Elements.php`; `'param' => '#reset-cache'` on an entry makes
  the page's JS clear its `sessionStorage` filter state on the next load (pattern in
  `Extensions/extensions-index.js`, `CallDetailRecords/call-detail-records-index.js`).
- No per-page permission registration: `SecurityPlugin` checks controller+action against
  `AclProvider` role rules.

## ACL
- Volt: `isAllowed('save')` / `isAllowed('index', 'Fully\\Qualified\\Controller')`. It is a
  compile-time Volt function (`VoltProvider`) and reads only literal string arguments;
  a variable argument silently falls back to checking `index`.
- JS: `ACLHelper` reads `window.CurrentPageACL`, generated by `Views/partials/acl-init.volt`
  for a fixed action list (index, modify, save, delete, copy, download, restore, edit,
  modifyiax, modifysip, viewSystemDiagnostic). A new action name must be added there or
  `ACLHelper.isAllowed()` returns false for it.

## Auth
- Authentication is JWT (`SecurityPlugin`, `JwtProvider`): Bearer header for AJAX,
  `refreshToken` cookie for page loads. There is no CSRF token layer; do not document or
  rely on one.

## Caches you must know about
- Translations are cached twice: in Redis via `managedCache` (DB 4, key prefix
  `_PH_MANAGED_CACHE:`, key `LocalisationArray:<versionsHash>:<lang>`, TTL 3600 s) and as
  the JS file `/var/tmp/www_cache/js/localization-<lang>-<versionsHash>.min.js`. The hash is
  `PBXConfModulesProvider::getVersionsHash()` (PBX + module versions), not content-based;
  after editing messages delete the JS file and flush/wait out the Redis key.
- Volt compiled templates go to `/var/tmp/www_cache/volt/` and are recompiled only in
  `debugMode`; on a production host delete that directory after editing `.volt` files.

## JS gotchas
- Never call `$()` in a top-level object-literal initializer; declare jQuery properties
  as `null` and resolve them in `initialize()`. Scripts are parsed before jQuery is
  guaranteed to be bound (issue #1054).
- Form posts go through the shared `Form` object (`main/form.js`); REST-style
  POST/PUT auto-detection is described in `sites/admin-cabinet/assets/js/RESTFUL-FORMS-GUIDE.md`.
- All backend calls go through `PbxApi`/`pbx-api-client.js`, which also handles 401
  redirects; do not hand-roll `$.ajax` to the REST API.
